# Feature Spec: Sample Preview with Virtual MIDI Keyboard

## Overview
Add an interactive sample preview system allowing users to audition recorded samples via a JUCE virtual MIDI keyboard. Samples playback through the application's audio output in real-time.

---

## Requirements

### Functional Requirements

1. **Virtual MIDI Keyboard Display**
    - Place JUCE `MidiKeyboardComponent` at bottom of main UI window
    - Display 49-key range (C2 to C7, MIDI notes 36-84)
    - Keyboard is non-interactive when no samples loaded
    - Keyboard is interactive when at least one sample exists

2. **Keyboard Input Handling**
    - When user clicks/presses key on virtual keyboard, generate MIDI note
    - MIDI note number must match the sample's note mapping
    - Support octave controls if using 88-key view (optional for v1)

3. **Sample Lookup & Playback**
    - Receive MIDI note from keyboard
    - Look up corresponding sample in `samples` map using note number as key
    - If sample exists: initiate playback
    - If sample doesn't exist: emit no sound (gracefully ignore)

4. **Audio Playback Engine**
    - Create `SamplePlaybackBuffer` class to manage active playback
    - Store: sample data, current read position, playback state (playing/stopped)
    - Support simultaneous playback of multiple keys (polyphonic)
    - Read audio data from buffer and send to audio output
    - Automatically stop when buffer exhausted

5. **Note On/Off Behavior**
    - Key press (Note On): start playback from beginning of sample
    - Key release (Note Off): fade out sample over ~50ms (prevent clicks)
    - Multiple presses: restart playback (don't layer)

6. **Thread Safety**
    - Sample data is read-only during playback (safe from audio thread)
    - Use atomic flag for playback state
    - No locking required (samples immutable after recording)

## Implementation Details

### New Classes

#### 1. `SamplePlaybackBuffer`
```cpp
class SamplePlaybackBuffer {
public:
  void startPlayback(const AudioBuffer<float>& sourceBuffer, 
                     double sourceSampleRate);
  void stopPlayback();
  
  // Called from audio thread
  void readBlock(AudioBuffer<float>& outputBuffer, int numSamples);
  
  bool isPlaying() const;
  
private:
  const AudioBuffer<float>* sourceBuffer = nullptr;
  int readPosition = 0;
  std::atomic<bool> isPlayingFlag { false };
  float fadeOutSamples = 2205; // 50ms at 44.1kHz
};
```

#### 2. `SamplePreviewManager`
```cpp
class SamplePreviewManager {
public:
  void initialise(const Map<uint8_t, SampleData>& samplesMap, 
                  double sampleRate);
  
  // Called when keyboard key pressed
  void playbackSample(uint8_t midiNote);
  
  // Called when keyboard key released
  void stopPlayback(uint8_t midiNote);
  
  // Called from audio thread in processBlock
  void processAudio(AudioBuffer<float>& outputBuffer, int numSamples);
  
  bool hasSamples() const { return !samplesMap.empty(); }
  
private:
  Map<uint8_t, SampleData> samplesMap;
  Map<uint8_t, SamplePlaybackBuffer> activePlaybacks; // One per key
  double sampleRate;
};
```

## Data Flow

```
User clicks keyboard key
    ↓
MidiKeyboardComponent generates MidiMessage::noteOn(noteNumber)
    ↓
ControlPanel::handleIncomingMidiMessage()
    ↓
SamplePreviewManager::playbackSample(noteNumber)
    ↓
Look up samplesMap[noteNumber]
    ↓
Create/start SamplePlaybackBuffer with found sample
    ↓
Next processBlock() calls previewManager->processAudio()
    ↓
SamplePlaybackBuffer reads from source buffer
    ↓
Output to audio device
    ↓
Key released → Note Off → fade out
```

## Constraints & Assumptions

### Technical
- Sample data is immutable during playback (no modifications allowed)
- Max 8 simultaneous playbacks (128 keys possible, but limit for CPU)
- Playback only uses samples that exist (silent for gaps)
- No pitch-shifting or time-stretching in v1

### Audio Behavior
- Playback always at original sample rate (no resampling)
- Fade-out duration: 50ms (hardcoded for v1)
- No volume/gain control in v1 (use system volume)

### UI Behavior
- Keyboard range fixed (no octave shift controls in v1)
- Keyboard always visible when samples exist
- No recording during playback (sampling disables keyboard)

### Memory
- One `SamplePlaybackBuffer` per active playback (max ~8)
- No persistent playback buffers after note ends
- Original sample buffers remain in memory (already allocated)
